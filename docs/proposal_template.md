# Proposal template

Write each proposal as a markdown file with exactly these sections. Aim for 700-1300 words: concrete and specific,
no padding. A reader who has not read the posts must be able to understand it.

```
# <Title>
cluster: <key> | stage-1 cost: $<n> | follows up: <post title(s) + LessWrong id(s)>

## 1. What the prior work showed
The specific findings this builds on (models, setups, effect sizes), including relevant work found on the web,
and what has ALREADY been done as follow-up — so that this proposal is demonstrably not a duplicate.

## 2. Question and why it matters
The one question stage 1 answers, and why the answer is interesting whichever way it comes out (or why not).

## 3. Stage 1 plan
Concrete experiments: models, datasets/environments/code being reused (with URLs), conditions, sample sizes,
metrics, controls and baselines, and the key analysis. Say what is reused vs built. List the steps in order.

## 4. Stage 1 cost estimate
Itemised (tokens x price, GPU-hours x price, fine-tuning runs), with a margin for reruns. Total <= $500.

## 5. What success looks like
The specific results (numbers, plots, comparisons) that would count as a clear, post-worthy finding; what a
null or ambiguous result would look like, and whether a null is still publishable.

## 6. Stage 2 (if stage 1 succeeds)
The experiments further funding would buy, with a rough cost.

## 7. Risks and how the plan handles them
The most likely ways this fails to produce an interesting output, and the mitigation or cheap early check for each.
```
