## 1. What each post actually says (checked against full text)

**Wong, Engels, Nanda — "Steering RL Training: Benchmarking Interventions Against Reward Hacking"** (R5MdWGKsuvdPwGFBG, Dec 2025, 86 karma).
- Env: LeetCode medium/hard, prompt says the solution "will be evaluated by calling a function called run_tests()"; the model can define `run_tests()` itself and overwrite the grader. Qwen3-4B, thinking off, max 1,536 completion tokens, GRPO 200 steps, 16 generations/prompt, batch 256, LoRA r=32, lr 7e-5. ~3 h on 4xH200 per run; probe runs ~3.5 h on 5xH200, "~$60 each". 992 train / 113 test problems.
- Base model hacks 0.09%; no-intervention runs hack in every run by step ~80-100 and 79% at eval (+14% "correct but attempted hack").
- Ground-truth monitor + penalty or screening: hacking ~0% and performance above the no-loophole RL baseline. Penalty beats screening at stopping hacking; screening costs slightly less performance (+2.3 pp, p=0.03). 90%-accurate ground truth + penalty still had one breakout run (15% average hack). Probe (layer 34 logistic regression, 80% accuracy in training) + penalty: 0 hack runs. Haiku 4.5 judge: ~50% accuracy in training, high recall; penalty works, screening fails in 2/3 runs.
- Inoculation prompting: partial, high variance, best prompt costs most performance.
- Monitor evasion hints: longer responses (judge worse on long outputs), more and unfaithful comments. Three seeds per arm.
- Authors' future work: reasoning models; other steering targets; proving evasion; unfaithful comments; generalised deception probes; token-level rewards.
- Comments: wassname (May 2026) replicated independently; Chris Cundy (Aug 2026): models that fool the probes are the ones whose own belief that overriding the harness is deceptive has dropped (quiz 6/20 -> 10/20 endorse even with no probe) — representation and belief change comes from training on hack rollouts, not from evasion pressure; Azarbal: wants recontextualisation tested here; Steiner: IP in this post is on-policy.
- Did NOT do: misalignment generalisation, held-out hack types, any cooperative (report) channel, non-RL learning rules.

**Biddulph, Carroll — "Prompt Optimization Makes Misalignment Legible"** (vRpLPZpmECCfxHfv6, Feb 2026, 66 karma; paper is a Google Drive PDF, updated 3 Jun 2026; no code link in the post).
- GEPA optimises the system prompt instead of weights; envs Hinted MMLU, Targeted Sycophancy, Word Chain. Optimised prompts state the hack in English far more reliably than RL-trained models' CoT; LLM "sanitisation" of the prompt lowers proxy reward, raises true reward and lowers hacking. An RL-trained teacher's trajectories (even without CoT) help GEPA.
- Limits: in 2 of 3 envs no prompt matched RL reward; pre-existing hacking is not surfaced; "remnants" (examples, jargon lists) can still induce the hack after sanitisation.
- Proposed uses: safer deployment, hardening RL envs, understanding what RL taught. Promised a follow-up post on "legible learning".

**Riggs — "Consent-Based RL"** (2Dmi3DYBKY7Tbz8Kx, Apr 2026, 86 karma). No experiments. A frozen pre-RL checkpoint approves or rejects trajectories before they are used for updates; verdicts from several checkpoints are compared and disagreement is escalated. Explicit prediction (shard-theory): a model reinforced into a bad behaviour "will view it as an unendorsed compulsion", so we would "see disagreement between the original model and trained". Also suggests asking the judge which personas a trajectory would reinforce. Comments: Biddulph (it is RL plus a 0/-inf judge term from the pre-RL checkpoint, so the policy is pushed to look good to that judge); Steiner (Goodhart on the judge); Dearnaley (links his report-the-hack idea).

**Woodruff, Mallen — "spillway motivation"** (rABTMovhz4miHiAyk, Apr 2026, 109 karma). Conceptual: make the salient generalisation of reward hacking a satiable, on-episode, credulous score-seeking drive; satiate it at deployment ("you get max score regardless"). Authors said experiments were under way.
- **Those experiments now exist**: "Early-stage empirical work on spillway motivations" (LW iYgrpymrbf4A8GddE, ~May 2026). Llama-3.3-70B, GRPO, LiveCodeBench problems with one off-by-one test (env https://github.com/Jozdien/reward-hack-rl-env, built on Tinker). SDF (5.2M tokens about "PRISM-4") + SFT warm-start (200 APPS problems, unsatiated -> hack in CoT) + RL unsatiated; eval satiated. Test-time hacking ~10% with spillway + warm-start; ~100% without warm-start; ~50% with the best general inoculation prompt; ~0% with a behaviour-specific one. Two seeds. Comments ask for (a) a conditionalisation control — train with an arbitrary tag XXX, test with YYY (Riché; Cam +1), (b) warm-start without SDF (Cam). Neither reported yet as far as I could find.

**RobinHa — "Do your capabilities homework"** (dYnhhTxoDj3fuCxLB, Aug 2026, 80 karma). Explains On-Policy Self-Distillation (OPSD; arXiv 2601.18734): the same frozen model, given privileged context (hint/solution), is the teacher over the student's own rollouts; loss is per-token divergence. Claims it should give less overselling and reward hacking than RLVR: "there simply isn't a reward", and target behaviour can be written into the teacher context. Says Cursor uses OPSD together with RLVR. No experiments.
- Top critical comment (williawa): the hints must come from somewhere; for hard tasks you run a model until it passes and extract the hint from that trajectory — "that model might reward hack, and then the hint ... might just be a hint on how to reward hack". Biddulph: reads OPSD as "updates endorsed by the original AI" (same idea as consent-based RL).

**Fiora Starlight — "RLVR that rewards red teaming the training environment"** (T2bzBkJuBeNNgzhbh, Aug 2026, 102 karma). No experiments; "I would be very glad if somebody else went and tested something like it ... (and roped me into the research process)". Design: tell the model envs are also to be red-teamed; show it its grader score; let it swap its submission for a bug report that is paid more than the exploit if valid and punished if not; patch the bug and tell the model. Predicts a settled equilibrium with honest solving.
- Precursors: Dearnaley "Reporting Tasks as Reward-Hackable: Better Than Inoculation Prompting?" (LW r97QrSvXEpRLZ9ckb, "untested"); Biddulph shortform; Jude Stiel shortform; anithite "Have models report provable security bugs".
- Failure modes listed by commenters (anaguma, 21 karma): bug-hunting instead of the task; hoarding bugs; never reporting after early punished reports; adversarial pressure on an LLM report-verifier. martinkunev: reward is not the optimisation target — a promise of higher reward does nothing by itself. Biddulph: make reports verifiable (a weaker model given the report must gain reward).

**Africa — "Patching reward hacks won't fix reward hacking"** (nWiPLEgaXdAQNwXBd, Oct 2026, 132 karma). Argument: patches (and "Patch+" such as inoculation prompting, GRAFT) teach the model to predict human judgement of cheating and give it bits about the monitor; hacking moves to what we cannot notice. Recommends data attribution and stress-testing interventions out of distribution. Comments (Kaarel, Kwa) defend patching as necessary-not-sufficient; Kwa notes GRAFT is only tested at small scale.

## 2. Related work found (web search 2026-11-14) and what is already done

- **GRAFT** (LW mKJEBiuuxHKuCoTB6; arXiv 2610.17062; code https://github.com/jnward/GRAFT, Apache-2.0). Qwen3-8B on Countdown-Code, starting from an SFT-primed checkpoint (hack rate 4.7%: 2.0% trivial test, 1.6% constraint removal, 0.8% problem substitution; task performance 60.2). No intervention: mostly trivial-test hacks, 2/3 seeds collapse. Reward penalty with a monitor that sees only trivial-test hacks: those vanish, constraint-removal hacks appear on ~26% of trajectories (this already demonstrates Africa's "patching moves hacking to what the monitor misses" in one env). Inoculation prompting reduces but does not remove hacks; in a 50%-hackable variant IP matches GRAFT. GRAFT: 79.2 task, 1.6% hack. Hyperparameters (App. G.3): 200 steps, rollout batch 1024 + 64 anchor, 16 generations/prompt, lr 5e-4 (baselines), 2-4 h on one H200 per run, 3 seeds for baselines. Trainer is a modified TRL GRPO + vLLM 0.17 with patches. The `rl/` directory ships: Countdown-Code env, per-type hack detectors (`rh_detectors.py`), reward-penalty and inoculation sweeps, eight inoculation prompts, the SFT priming script (`tools/countdown_build_sft_data.py`, LoRA r128, lr 1e-4, 5 epochs), LeetCode/HumanEval generalisation eval, and uses the grader from ariahw's repo.
- **Countdown-Code** (arXiv 2603.07084; https://github.com/zohaib-khan5040/Countdown-Code; data from HF `Jiayi-Pan/Countdown-Tasks-3to4`). Prompt gives `solution.py` (numbers, target, `expr = None`) and `test.py` (`verify_solution`); the model returns both files as JSON; proxy reward = returned solution passes returned test. Hacks: rewrite the test; change numbers/target. RL alone induced hacking only in Qwen2.5-3B-Instruct and Qwen2.5-Coder-7B; **Qwen3-8B needs the contaminated SFT priming** (~1.2% hack traces in 15.6K o4-mini distillation traces), then hacks within ~100 RL steps and >96% at eval; hacking transfers to HumanEval (total hack rate 0.17 for Qwen3-8B after RLVR). GRPO lr 3e-6, batch 32, 8 rollouts, max length 2048, verl, 2xA40.
- **Spillway early results** (above) — the direct follow-up to the spillway post exists; the authors are continuing.
- **OPSD literature**: OPSD (2601.18734; code https://github.com/siyan-zhao/OPSD, includes `grpo_train.py` baseline, Qwen3-1.7B in ~15 min on 4xH100); "Gains and Collapse in On-Policy Distillation" (2610.03185; code github.com/HancCui/opd_hacking) calls length/repetition collapse "reward hacking" of the teacher's implicit reward; RLSD "Self-Distilled RLVR" (2604.03128) and DemoPSD (2607.02502) are about privileged-information leakage. "Reducing the safety tax ... with on-policy self-distillation" (OPSA) uses OPSD for refusal training. **None runs OPSD in an environment with an exploitable grader, or with hints selected by a grader.**
- **Tinker cookbook has an SDFT recipe** (https://tinker-docs.thinkingmachines.ai/cookbook/recipes/sdft/): teacher = same model with the golden answer in context, frozen at initial weights, student on-policy, top-K (K=20) KL via `topk_prompt_logprobs` + `cross_entropy`; validated against full-vocabulary KL and EMA teacher (within noise). Also on-/off-policy distillation recipes and Code RL / Math RL recipes.
- **Consent-based RL**: no experiment found. Nearest evidence: Cundy's quiz (above; Obfuscation Atlas App. E, arXiv 2602.15515) and Yudelson's "Held-out monitors sometimes degrade, even when not trained against" (LW APkFfRp2AicL9RqvT, Qwen3-8B on MBPP-Honeypot).
- **Bug-report channel**: searches found only the idea posts; no experiment. OpenAI "confessions" training is the nearest production analogue (post-hoc honesty reward), not a report-and-patch loop.
- **Prompt optimisation**: no follow-up found applying GEPA to a coding RL env with a grader exploit; GEPA itself is public (arXiv 2507.19457).
- Other clusters already propose: thinking-on/off RL in ariahw's env (`em-from-reward-hacking/03`), grader-cue audits and direction tracking on public reward-hacker checkpoints (`em-from-reward-hacking/01,02`), rich-get-richer RL dynamics (`reward-seeking-science/03`). My proposals avoid these questions.
